# MJ Prompt Studio ユーザーマニュアル

MJ Prompt Studioは、画像生成の前に考えをPromptへ整え、生成後の結果から次の一手を決めるための**制作支援アプリ**です。画像生成サービスへログインしたり、Promptを送信したり、画像を投稿したりはしません。

このマニュアルは、ボタンを押す順番だけでなく、**どんな悩みを解決する機能なのか、いつ使うべきか、操作すると何が変わるのか**を説明します。最短で一度試すだけなら、アプリ内の「使い方」から[最初に試す流れ](quick-start.md)を開いてください。

## 制作を始める前に: このアプリが担当すること

画像生成では、イメージを言葉にし、生成して、画像を見て、言葉を選び直します。MJ Prompt Studioは、そのうち**言葉を設計すること、試す条件を整理すること、結果から改善点を残すこと**を助けます。

生成サービスへPromptを手動で貼り付け、生成した画像を手動で取り込むのは、単なる手間ではありません。このアプリは外部サービスのアカウント、ログイン状態、投稿先、生成・保存の判断を扱わないためです。どのサービスで試すか、どの画像を保存・共有するかは、常にあなたが決めます。

### いまの悩みから画面を選ぶ

- **作りたい絵はあるが、Promptにどう書けばよいかわからない**: [Composer](#composer)で、制作意図を要素に分け、コピーできるCompiled Promptへ整えます。
- **材料がない、または既存の文章を別の方向に作り直したい**: [Prompt Workshop](#prompt-workshop)で、新しい案を出す作業と文章を変換する作業を分けます。
- **好きな色・構図・質感を言葉にできない**: [Reference Library](#reference-library)で、参照画像から再利用できる観察語彙を取り出します。
- **何が効いたのか比較したい**: [Matrix Lab](#matrix-lab)で、固定する条件と変える条件を分け、比べられるVariantを作ります。
- **外部サービスで作った画像を次の改善につなげたい**: [Result Review](#result-review)で、画像を元のPromptと結び付け、改善案にします。
- **AI接続、保存、出力の方針を変えたい**: [Settings](#settings)で、影響を理解して設定します。

すべての画面を順番に使う必要はありません。すでに試したいPromptがあるならPrompt Workshopから、生成画像があるならResult Reviewから始められます。

## 制作の基本ループ: なぜ「作る」と「見直す」を往復するのか

1. **意図を言葉にする**: Composerで、被写体、構図、光、色、雰囲気を分けて考えます。
2. **生成サービスで試す**: Compiled Promptをコピーし、使う外部サービスへ自分で貼り付けて生成します。
3. **画像を見て判断する**: 良かった点と違った点を、Result Reviewで元のPromptと一緒に残します。
4. **次の一手を一つ選ぶ**: 語彙を直すならComposer、方向を作り直すならPrompt Workshop、条件比較ならMatrix Labへ戻ります。

一度にすべてを直すと、何が効いたかを判断できません。比較したいならMatrix Lab、方向そのものを変えたいならPrompt Workshopを使うと、次の試行の理由を残せます。

## AI接続とデータの扱い

### API keyが必要な場面

AIによる構造化、語彙提案、画像分析、レビューを実際に使うにはAPI keyが必要です。起動前に環境変数 `OPENAI_API_KEY` を設定するか、Settingsでこのセッションだけ適用、またはOS資格情報ストアへ保存して使います。起動時には互換名の `OPENAI_KEY`、`MJPS_OPENAI_API_KEY`、保存済みのOS資格情報ストアもこの順で確認されます。

API keyがない場合、通常起動ではAI実行を開始せず、画面下部とSettingsに理由と設定導線を表示します。Mock LLMでの開発用確認は `MJPS_LLM_MODE=mock` を明示した場合だけです。実APIの接続確認は`Test`で実行し、明示的Mockでは接続成功として扱いません。

### 実行プロファイルを確認する理由

AIの実行構成はアプリ全体で固定されており、Settingsの`AI execution profile`は実効値を確認するための表示です。ここで機能ごとにモデルや推論強度を選ぶ必要はありません。変更できるのは、機能ごとの語彙量などモデルに依存しない項目です。過去の機能別設定がある場合は、起動時に語彙量だけを引き継ぎます。

### AIに何が送られるか、なぜ確認が必要か

AI支援を実行したときだけ、その操作に必要な入力がAIへ送られます。たとえば参照画像の分析や生成結果のレビューを実行すると、選んだ画像と必要な情報が対象になります。取り込んだだけでは分析は始まりません。

AIの提案は、制作物を勝手に置き換える指示ではありません。PatchやNext Promptが出たら、理由・差分・適用先を確認してから使ってください。自分の意図を残したい、または根拠が弱いと感じる場合は、適用せずに手動編集できます。

### Privacy modeを選ぶ場面

Privacy modeは、Responses API側での保存と会話IDの継続を使わない設定です。継続した会話よりも保存を抑えたいときに有効にします。これはAI分析そのものを止める設定ではありません。画像分析やレビューを実行するなら、その操作に必要な画像・情報は送られます。送信を避けたい画像は、分析やAI Reviewを実行しないでください。

## プロジェクトと作業の戻し方

プロジェクトは、一つの制作テーマをまとめる箱です。新しいテーマを始めるときはHeaderの`New`で分けると、あとからPrompt、参照素材、結果を混同しにくくなります。

Composerには「未保存の変更」または「保存済み」が表示されます。途中の考えを残したいときは`保存`を押してください。保存済みのPromptDocument状態に戻すにはHeaderの`Undo`と`Redo`を使います。入力欄の外では、`Alt+Shift+S`で保存、`Alt+Shift+Enter`でCompile、Compiled Promptがあるときは`Alt+Shift+C`でコピーできます。入力欄を編集中にこれらのショートカットが実行されることはありません。

## Composer

### この画面が解決すること

Composerは、新しい画像を作り始めるときに、頭の中のイメージを**一つのコピー可能なPrompt**へ整える画面です。「かわいい」「映画的」のような感覚語をそのまま抱え込まず、被写体、動き、環境、構図、光、質感、色、スタイルといったBlockに分けて確認できます。

すでに文章があり、方向を大きく変えたいときはPrompt Workshopの方が適しています。Composerは、制作意図を構造化して、外部サービスへ投入する前の一案を固めたいときに使います。

### 操作前に決めること

- 作りたい画像を一文で説明します。完成したPromptでなくて構いません。
- 特に残したい要素があれば、被写体、雰囲気、色、構図の優先順位を考えておきます。
- すでに生成画像がある場合は、先にResult Reviewで違いを整理してから戻ると、次に直す箇所を選びやすくなります。

### 操作すると何が起きるか

`AI Brief から構造化`は、短い制作意図をPrompt Blocksの下書きへ分解します。各Blockはその後に手動で直せます。`Compile`は、Blockと選んだパラメータをまとめて、コピー用のCompiled Promptを作る操作です。コピーは外部サービスへの送信ではなく、あなたが貼り付けるための準備です。

### 最短手順

1. `AI Brief`に、作りたい画像を日本語で短く書きます。
2. `AI Brief から構造化`を押し、返ったBlockを確認します。
3. 意図と違う語、足りない条件、残したい表現をBlockごとに直します。
4. `Compile`を押し、`Compiled Prompt`を確認します。
5. コピーして、選んだ画像生成サービスへ手動で貼り付けます。

### 迷ったときの補助

- **AI補完 / 候補 / 専門語化**: 表現の選択肢が欲しいときに使います。意図そのものを決めてもらう操作ではありません。
- **短縮**: 意味を保ちながら説明を短くしたいときに使います。全体の方向を作り直すならPrompt Workshopの「文字数のみ調整」も選べます。
- **説明**: 専門語や提案の意味を確認したいときに使います。
- **Parameter Advisor**: 表現ではなく、利用可能なパラメータの組み合わせで調整したいときに使います。手で選んだ値は次のCompileに使われます。
- **Prompt Doctor**: 何を直すべきか判断できないときに使います。問題とPatch候補を確認し、納得したものだけ適用します。

AI処理が完了するまでの状態は下部の[Jobs](#jobs)で確認します。入力不足でCompileできないときは、AI BriefまたはPrompt Blocksを先に入力してください。

## Prompt Workshop

### この画面が解決すること

Prompt Workshopは、**材料なしで案を出す作業**と、**すでにあるPromptを目的別に変える作業**を分ける画面です。二つを混ぜないことで、「発想が必要なのか」「文章を直せばよいのか」を先に選べます。

ComposerのBlockを細かく整える画面ではありません。比較する条件を管理したい場合はMatrix Lab、生成後の画像を評価したい場合はResult Reviewを使います。

### 材料がないとき: ゼロからPromptを生成

アイデアの出発点がないときに使います。件数、カオス度、出力言語、任意ガイダンスを指定すると、複数の案が返ります。カオス度を上げるほど、意外な組み合わせを探す幅を広げます。完全に同じ案を除外する設定は、比較する候補数を無駄に増やしたくないときに選びます。

1. 必要な件数と出力言語を選び、必要なら任意ガイダンスを加えます。
2. `Prompt案を生成`を押します。
3. 気になる案だけを選び、コピーするか、作業中のPromptとして読み込みます。
4. そのまま外部サービスで試すか、Composerへ取り込んで細部を整えます。

### 既存Promptを整えたいとき

- **世界観整形**: 主題を残しながら、一枚の画像として読みやすい方向へまとめたいときに使います。文字数だけを変えたいなら選びません。
- **カオスミックス**: 元の核を残して、予想外の視覚表現を足したいときに使います。一つずつ比較条件を検証したいならMatrix Labを使います。
- **文字数のみ調整**: 意味・主題・画風を保ったまま、短く・長くしたいときに使います。新しい表現や除外語句を反映したいときには向きません。
- **LLMアレンジ**: プリセットの方向と強度を使って視覚表現を整えたいときに使います。主題そのものを決め直すなら、ゼロから生成またはComposerへ戻ります。

世界観整形、カオスミックス、LLMアレンジにはSettingsのPrompt除外語句が適用されます。文字数のみ調整には適用されません。これは、意味を保つ操作で意図しない語を消さないためです。結果はコピー、作業中のPromptへの反映、または確認付きのComposer取り込みから選べます。

## Reference Library

### この画面が解決すること

Reference Libraryは、好きな画像の「何が好きか」を、色、構図、照明、質感などの**次に使える言葉**へほどく画面です。画像をそのまま外部サービスへ送るための機能ではなく、制作判断の材料を整理するために使います。

画像を分析に送りたくない、または自分の観察だけで十分なときは、取り込んだ画像の確認やタグ整理に留め、分析アイコンを押さないでください。結果の良し悪しを判断したいときはResult Reviewが適しています。

### 操作前に確認すること

- 自分が取り込んでよい画像かを確認します。
- 分析する場合は、選んだ画像と必要な情報がAI分析の対象になることを理解します。
- 画像を削除するときは、以後の参照に使えなくなるため、不要であることを確認します。

### 最短手順

1. `Add`またはドラッグ&ドロップで画像を取り込みます。
2. プレビュー、形式、サイズ、カラーパレットを確認し、何を参考にしたいかを言葉にします。
3. 分析してよい画像だけ、分析アイコンを押します。
4. 返った照明・色・構図・質感・語彙を確認します。
5. 使いたい語彙を、ComposerへPatch候補として戻します。差分を確認してから適用します。
6. 後で探せるように、タグを編集して保存します。

画像のプレビューは安全なasset endpointで表示され、画面にはOS上のローカルパスを表示しません。不要な素材を削除するときは確認ダイアログを通します。

## Matrix Lab

### この画面が解決すること

Matrix Labは、「構図と照明のどちらが効くのか」のように、**何を比べるかを先に決めてから複数案を試す**画面です。感覚的にPromptを大きく変え続ける代わりに、固定する条件、変える軸、見る観点を残せます。

最初の一案を考えるならComposerまたはPrompt Workshopを使います。生成済みの画像を評価するならResult Reviewです。Matrix Labは、比べたい仮説があるときにだけ使います。

### 操作すると何が起きるか

`AI Plan`は、入力した目的から比較軸、固定条件、評価観点を提案します。`Generate`は、その計画に沿ってVariantを展開します。Variantの生成は保存されるため、同じ計画を後で見返せます。外部サービスへの送信は行われず、必要なVariantをあなたがコピーまたはCSV/Markdownで出力します。

### 最短手順

1. Objectiveに「何を比較して、何を判断したいか」を書きます。
2. `AI Plan`を押し、比較軸と固定条件が意図に合うか確認します。
3. `Generate`でVariantを作ります。
4. 選んだVariantだけをコピーするか、まとめてCSV/Markdownへ出力します。
5. 外部サービスで試し、画像をResult Reviewへ取り込んで比較します。

一度に多くの条件を変えるほど、違いの理由は追いにくくなります。目的が曖昧なままVariantを増やすより、Objectiveを一文で書き直してから計画を作ってください。

## Result Review

### この画面が解決すること

Result Reviewは、外部サービスで生成した画像を見て「次は何を変えるか」を決める画面です。画像だけを見るのではなく、元のPromptとparameters snapshotを一緒に残すため、良かった点・足りない点を次の試行へつなげられます。

まだ画像を生成していないときや、新しい案を考えたいだけのときは使いません。まずComposer、Prompt Workshop、またはMatrix Labで試すPromptを用意します。

### 操作前に確認すること

- 外部サービスで生成した画像をローカルに保存します。
- AI Reviewを行う場合は、選んだ生成結果画像と必要な制作情報がAIの対象になります。
- どの画像がどのPromptの結果なのかを見失わないよう、同じ制作テーマのプロジェクトを開きます。

### 最短手順

1. `Import`で保存した画像を取り込みます。
2. 表示されたSource Promptとparameters snapshotを確認します。
3. AI Reviewを実行する場合は、スコア、良い点、課題、Next Prompt Candidateを確認します。
4. 改善案を使うときだけ`Next Prompt`を選び、差分を確認してComposerへ適用します。
5. 複数の結果なら`Compare`で並べ、どの条件を次回残すか決めます。
6. コピー・出力前に不安があるときは`Final Audit`で最終確認します。

AI Reviewの提案は評価の補助です。あなたの用途や好みの代わりにはなりません。Next Promptを使わず、良かった点だけを手でComposerへ反映しても構いません。

## Settings

### この画面が解決すること

Settingsは、AI支援を使うか、どこまで保存を抑えるか、テキストPromptに何を含めるかを選ぶ画面です。制作のたびに開く必要はありません。接続や出力の方針を変えたいときだけ使います。

### API keyの使い分け

- **環境変数で起動**: ターミナルから起動し、起動時にキーを渡したいときに使います。起動時に自動で読み取ります。
- **このセッションだけで使用**: 端末に保存せず、今回だけAI支援を使いたいときに使います。アプリを閉じるまでの利用に限定します。
- **OS資格情報ストアへ保存**: 自分の端末で、次回以降もキーを安全に呼び出したいときに使います。OSの資格情報ストアに保存します。
- **OS資格情報ストアから読み込んで使用**: すでに保存したキーを現在のセッションへ使いたいときに使います。キーの値は画面に表示しません。

`接続テスト`は、実AIを使う前にAPI keyと基本的な接続状態を確認するためのものです。生成結果の品質や、あなたのPromptが目的に合うことを保証する操作ではありません。また、構造化AI処理ごとの形式や、その時点の応答保存設定まで成功することは保証しません。構造化が失敗したときは、下部のJobsに表示される原因と手順を確認してください。

### AI execution profileと語彙設定

AI execution profileは、アプリが使う固定の実行構成を確認する読み取り専用の表示です。機能ごとにモデルや推論強度を変える画面ではありません。出力される候補の量を変えたい場合だけ、Feature vocabulary preferencesで機能ごとの語彙量を選び、`語彙設定を保存`します。

### テキストPrompt出力と除外語句

`テキストPrompt出力`は、構造化されたオプションをテキストPromptにも付けるかを選ぶ設定です。OFFにしてもPromptParametersとJSON snapshotは保持されます。外部サービスへ貼り付ける文字列を簡潔にしたいときはOFF、構造化オプションも一緒に確認したいときはONを選びます。

`Prompt除外語句`は、創作系の生成・変換で繰り返し避けたい語を1行ずつ管理する設定です。新規生成、世界観整形、カオスミックス、LLMアレンジに適用されます。文字数のみ調整、既存Promptの保存、すでに作られた結果には適用されません。これは、意味を維持する操作や過去の記録を意図せず変えないためです。

## Jobs

### この表示がある理由

AIによる構造化、提案、画像分析、レビューは、すぐに終わらない場合があります。Jobsは、待っているのか、完了したのか、失敗して入力を見直すべきかを区別し、画面を閉じずに回復するための一覧です。

- **待機中**: 実行順を待っています。不要なら取り消し、必要なら対象画面を開いたまま待ちます。
- **実行中**: AI処理中です。完了通知を待ち、不要になったら取り消します。
- **完了**: 結果を対象画面で確認できます。提案・出力を確認し、必要なものだけ適用・コピーします。
- **失敗**: 結果は適用されていません。原因と「次にできること」を確認します。API key・認証・権限・応答保存はSettingsを開きます。利用枠または請求上限の場合はOpenAI Platformで利用枠・請求状態を確認してから、同じJobを再試行します。一時的なリクエスト制限・一時障害は少し待ち、ネットワークは接続を確認してから、必要な場合だけ再試行します。
- **取消済み**: 処理を止めました。結果は適用されていないため、必要なら元の操作をやり直します。

Jobsの詳細では対象、実行設定、原因、次にできることを確認できます。構造化形式または実APIリクエストの失敗では入力は保持されています。再試行しても続くときは、画面にproviderの生エラーを表示しないため、アプリを更新してから再試行するか、Settingsの接続とPrivacy modeを確認してください。

## Export

### なぜ形式を選ぶのか

Exportは、次にどこで使うかに合わせて制作記録を持ち出すための操作です。画像生成サービスへ試すだけならPrompt only、制作の経緯を読み返すならMarkdown record、別のツールで扱うならJSON snapshot、比較案を渡すならMatrix CSVまたはMatrix Markdownを選びます。

エクスポートにはPrompt、パラメータ、制作記録が含まれる場合があります。共有する前に、外部へ出してよい内容かを確認してください。ブラウザのClipboard APIが使えない場合は、手動コピー用のtextareaが表示されます。

## 困ったとき

- **どの画面から始めるか迷う**: 「作りたい一枚を言葉にする」ならComposer、「案を出す・文章を変える」ならPrompt Workshop、「比較する」ならMatrix Labです。
- **AIの提案を採用してよいか迷う**: PatchやNext Promptの差分を確認し、残したい意図が消えるなら適用しません。手動で一部だけ直せます。
- **AI処理が終わらない・失敗した**: 下部のJobsで状態、原因、次にできることを確認します。Settingsを開く案内が出た場合はAPI key・権限・Privacy modeを確認します。利用枠または請求上限の案内では、OpenAI Platformの利用枠・請求状態を確認してから再試行します。一時的なリクエスト制限または一時障害の待機案内では少し待ちます。その他は入力を保持したまま明示的に再試行できます。
- **画像をAIへ送りたくない**: Reference Libraryの分析、Result ReviewのAI Reviewを実行しません。取り込み・整理だけに留めます。
- **手順を画面上で確認したい**: 右下の`使い方`を開き、`この画面の使い方へ`を押すと、現在の画面に対応する節へ移動します。
