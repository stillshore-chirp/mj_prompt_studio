# AIエージェントレビュー・プロトコル

## 目的

「良さそう」ではなく、観察、Pass/Fail、反証、証跡提出を行います。

## ロール

実装者、価値評価者、初見ユーザー、認知負荷監査者、アクセシビリティ監査者、視覚階層批評者、状態設計監査者、熟練者評価者、信頼感評価者、反証レビュアー、検証報告者の観点を分けます。1つのエージェントが複数ロールを担っても、観点を混同しません。

## 実行順序

```text
scope棚卸し
-> ユーザー価値
-> 初見シミュレーション
-> state matrix
-> 認知負荷
-> accessibility
-> 視覚階層
-> copy
-> 熟練者効率
-> 満足感・信頼感
-> 反証レビュー
-> 証跡・未実行・残リスク
```

## 反証レビュー

- 実装を褒める前に完了不可理由を探す。
- 通常状態以外とhappy path以外の証跡を見る。
- 自動検査で見つからない迷い、効率、信頼を探す。
- 初心者向け配慮が熟練者を遅くしていないか疑う。
- screenshotやtest logが実際の対象と最新headを示すか確認する。

## 出力制約

「問題ありません」だけの報告、未検証の確認済み化、AI推定を実ユーザー事実として書くこと、理論名だけの指摘、根拠なきP0格下げを禁止します。Pass/Fail、P0/P1/P2、証跡、未実行、残リスクを必須とします。

PRではCI成功後にCodex review、review comment、review threadを確認します。レビュー往復の上限と収束条件はルート `AGENTS.md` を優先します。
