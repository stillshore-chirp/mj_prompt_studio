# AIエージェントレビュー・プロトコル

## 目的

「良さそう」ではなく、観察、Pass/Fail、反証、証跡提出を行います。

## Role

実装者、価値評価者、初見ユーザー、認知負荷監査者、accessibility監査者、視覚階層批評者、状態設計監査者、熟練者評価者、信頼感評価者、反証reviewer、検証報告者の観点を分けます。1つのエージェントが複数roleを担っても、観点を混同しません。

## 実行順序

```text
対象面とscopeの棚卸し
-> ユーザー価値
-> 初見simulation
-> state matrix
-> 認知負荷
-> accessibility
-> 視覚階層
-> copy
-> 熟練者効率
-> 満足感・信頼感
-> 反証review
-> 証跡・未実行・残リスク
```

GitHub共同作業面だけの場合は、文言、項目、構造、link、公開安全性に絞り、製品UI向けの全工程を機械的に適用しません。

## 反証review

- 実装を褒める前に完了不可理由を探す。
- 通常状態以外とhappy path以外の証跡を見る。
- 自動検査で見つからない迷い、効率、信頼を探す。
- 初心者向け配慮が熟練者を遅くしていないか確認する。
- screenshotやtest logが実際の対象とlatest headを示すか確認する。
- adapterに正本の本文が複製されていないか、path scopeが広すぎないか確認する。

## 出力制約

「問題ありません」だけの報告、未検証の確認済み化、AI推定を実ユーザー事実として書くこと、理論名だけの指摘、根拠なきP0格下げを禁止します。Pass/Fail、P0/P1/P2、証跡、未実行、残リスクを必須とします。

## PR reviewの収束

- latest meaningful changeに対する必須CIと利用可能なreviewを確認する。
- actionableな指摘を修正した場合は、変更後のheadでCIと該当reviewを再確認する。
- 変更のないheadでclean reviewを増やすためだけの反復を行わない。
- reviewが提供されない環境では、代替自己review、未確認範囲、残るリスクを記録する。
- merge、close、releaseは別の明示指示がある場合だけ行う。
