# ユーザー価値・目的適合ゲート

分かりやすくても目的を助けないUIは良いUXではありません。

## 基本質問

対象ユーザー、利用文脈、達成したい結果、助ける理解・判断・行動・回復・継続、UIがない場合の困り事、既存導線での代替可否、追加情報や操作の必要性、削除候補を説明します。目的は画面名ではなく結果で書きます。

## Job / Task / Decision

- Job: 画像生成promptを設計・検証・改善する大きな目的。
- Task: brief入力、候補比較、Patch確認、copy、reference取込など画面上の作業。
- Decision: 候補、parameter、reference、修正案を選ぶ判断。
- Feedback: 保存、生成、copy、適用の結果理解。
- Recovery: failure、取消、再試行、復元。

画面やcomponentは少なくとも1つのTask、Decision、Feedback、Recoveryを明確に助けます。

## P0 / P1

対象、目的、支援する理解・判断・行動を説明できない、主要情報が意思決定に使われない、実装都合を価値として説明する場合はP0です。価値はあるが文脈が曖昧、別画面と重複、補助操作が目立ちすぎる場合はP1です。

## 削る判断と成功指標

内部ID、使われない件数、常時表示の長文説明、重複button、理解できない内部用語を削る候補にします。task完了率・手数、入力error、再試行、誤操作、Undo、help参照などを検証仮説にできますが、未計測を計測済みと報告しません。
