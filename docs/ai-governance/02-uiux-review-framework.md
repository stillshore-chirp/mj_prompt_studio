# UI/UXレビュー・フレームワーク

## 1. UI/UX品質の定義

対象ユーザーが特定の文脈で目的を達成でき、その過程が分かりやすく、見やすく、操作しやすく、失敗しても回復でき、慣れれば速く、安心して使えることを品質とします。

すべてのユーザー可視変更で、対象ユーザー、目的、支援する理解・判断・行動、現在地、最初の有意味な行動、結果予測、待機・空・失敗・無効時の次行動、反復効率、信頼感を説明します。

## 2. レビューパイプライン

### 2.1 目的・価値

- 対象ユーザーと達成したい結果を特定する。
- UIが助ける判断・行動・理解・回復を明確にする。
- 実装都合の情報や不要な操作を価値として正当化しない。

### 2.2 初見理解

3秒だけ見た前提で、画面目的、現在地、主操作、最初の行動、変化を判断します。実装知識がなければ答えられない箇所は修正候補です。

### 2.3 認知負荷

必要情報を画面へ出し、内部用語や前画面の記憶を要求せず、選択肢を制御し、高度な機能を段階的に開示します。

### 2.4 状態設計

通常だけで判断せず、該当しない理由がない限り、通常、読み込み中、空、検索結果なし、部分データ、エラー、入力エラー、無効、権限不足、オフライン・API未設定・利用不可、狭幅、文字拡大、長文・大量データをstate matrixへ記録します。

MJ Prompt StudioではLLM jobのqueued/running/succeeded/failed/cancelled、API key未設定、mock/実API、ローカルasset欠損、DB破損・復旧も関連時に含めます。

### 2.5 視覚階層

重要情報と主操作が自然に見え、補助情報が妨げず、グルーピング、余白、整列、タイポグラフィが理解を助けることを確認します。

### 2.6 アクセシビリティ

キーボード、可視focus、自然な順序、accessible name、表示labelとの一致、見出し・landmark、状態通知、contrast、target size、文字拡大、reflow、色以外の手がかりを確認します。

### 2.7 コピー

ユーザーの言葉、結果が分かる動詞、原因・影響・回復を示すerror、次行動を示す空状態、disabledの理由・有効化条件、責任転嫁しないtoneを確認します。ユーザー可視の禁止表記も検査します。

### 2.8 熟練者効率

反復タスクの手数、再入力・再選択、入力保持、再試行、前回設定、shortcut、一括操作、復帰を確認し、初心者向け説明が恒常的な障害にならないようにします。

### 2.9 満足感・信頼感

待機、成功、失敗、削除、外部送信、LLM解析、データ保存、API key、Privacy modeの対象・影響・回復・取り消し可否が誠実に伝わることを確認します。

### 2.10 反証レビュー

実装を落とすつもりで、価値の曖昧さ、初見依存、状態漏れ、アクセシビリティ、熟練者効率、信頼を損なう挙動、happy pathだけの証跡を探します。

## 3. P0 / P1 / P2

### P0: 完了不可

- 対象ユーザー、目的、支援価値を説明できない。
- 画面目的、現在地、対象範囲、最初の行動が分からない。
- 主操作が埋もれる、または意味不明なicon-onlyである。
- 主要状態が混ざり、errorに原因・影響・回復がない。
- disabledの理由や有効化条件が分からない。
- キーボード、focus、name/label、contrast、target、構造に重大問題がある。
- 危険操作、削除、外部送信、個人情報、API key、ユーザー資産に予防・確認・回復がない。
- 反復タスクが不要な説明、確認、再入力で恒常的に妨害される。
- 成功・失敗・待機が分からない、またはユーザーを責める。
- 必須証跡がない、未実行検証を成功扱いする。

### P1: 原則として同じ変更内で修正

- scope、表示優先度、用語が曖昧または不一致。
- 空・成功・error後の次行動が弱い。
- 回避可能だが反復手数が多い。
- 説明や警告が冗長で効率・信頼を損ねる。

### P2: Issue化可

微細な余白・文言・順序、将来のshortcutや一括操作、追加説明、実利用調査が必要な改善仮説です。

P0を格下げする場合は、完了不可でない根拠を記録します。

## 4. 数値目安

既存design systemを優先し、なければ通常本文16px以上、長文行高1.5以上、通常text contrast 4.5:1以上、大きい文字・非text部品3:1以上、操作対象24×24 CSS px以上、明確で隠れないfocusを目安とします。

## 5. AIレビューの限界

AI初見シミュレーションは実ユーザーテストではありません。得ていない反応を事実化せず、未実施を明記し、重大な価値・迷い・満足感の仮説は後続検証として残します。
