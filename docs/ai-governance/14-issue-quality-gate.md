# Issue 品質ゲート

Issueは変更一覧ではなく、第三者が必要性、判断根拠、完了状態を検証できる追跡単位です。

## 必須内容

該当する `.github/ISSUE_TEMPLATE/` を使い、次を記載します。

1. 背景・判断理由: なぜ必要か、なぜ今か、未対応時に誰が困るか。
2. 根拠・不確実性: 確認済み事実、ユーザー提示情報、code・公式仕様・log・実data、仮説、未確認事項。
3. 現状の問題と影響: 利用者、運用、保守、data、securityへの影響。
4. 目的と成果: 実装項目ではなく作業後に成立させたい状態。
5. 対応範囲と非対象: 今回行うこと、意図的に行わないことと理由。
6. 受け入れ条件と検証: 第三者がPass/Failできる観測結果と確認方法。
7. リスクと未確認: 既存挙動への影響、実行できない検証、残る不確実性。

## 事実・判断・仮説の分離

| 種別 | 書き方 |
|---|---|
| 確認済み事実 | 何をどの証跡で確認したか |
| ユーザー提示情報 | リポジトリ側で再検証したか |
| 判断 | どの事実・目的・制約から選んだか |
| 仮説 | 未確認であることと確認方法 |
| 未確認事項 | 理由、影響、次の最短action |

外部評価や第三者資料は、出典を示すだけで確認済み事実へ格上げしません。現行仕様や高risk判断は公式資料、code、test、log、実dataで確認します。

## 既存Issueと更新

既存Issueがscopeを含んでも必須内容が不足する場合は、実装前に本文またはcommentへ理由、根拠、成果、非対象、受け入れ条件、riskを補います。実装中にscopeや事実が変わればIssueを更新し、重要判断をPRだけへ閉じ込めません。

## 公開安全性

Issueへ秘密情報、認証情報、個人情報、prompt全文、画像、実運用log原文、追跡可能IDを貼りません。公開できない根拠は証跡種別、公開可能な観測、判断への影響、非公開範囲、次の確認へ要約します。

## Pass / Fail

理由、根拠、成果、scope、非対象、受け入れ、検証、riskが第三者に読み取れ、事実と未確認が分離し、受け入れ条件が観測可能ならPassです。変更fileだけ、曖昧な「改善」、仮説の断定、非対象なし、検証不能範囲の隠蔽はFailです。FailのIssueで実装を開始しません。
